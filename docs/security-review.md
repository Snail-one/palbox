# 登录与 TOTP 安全审核

审核基线：`9144db2`。范围包括首次初始化、密码登录、TOTP、恢复码、会话、CSRF、代理转发头、静态文件边界、登录日志、账号弹窗和绑定二维码。

原始审核采用代码审查、临时 HTTP 服务复现和实际 Chromium 浏览器验证；没有访问现有服务器或读取现有管理员资料。下方原始发现描述基线行为，修复状态描述随后完成的代码加固；结论只覆盖本次测试场景。

## 修复状态

- **F1 已修复**：前端默认忽略转发头，前后端分别用 `PALBOX_TRUSTED_PROXIES` 显式指定可信 IP/CIDR；链路解析停在第一个非可信跳点，非法链不跳过。两个 Compose 文件固定前端地址，后端只信任该容器。原生双进程默认只信任精确回环地址。
- **F2 已修复**：启用、关闭 TOTP 和重置恢复码时，清除全部旧会话、挑战与绑定，给当前浏览器重新签发 Cookie、CSRF。旧 Cookie 返回 `401`，新 Cookie 搭配旧 CSRF 返回 `403`；当前页面自动接收新凭据并重连日志。
- **第二因素补充加固**：失败同时受 IP 和管理员账号预算约束，账号累计 10 次失败冷却 5 秒；更换 IP、重复提交正确密码不能清零。预算在串行写入内再次校验，伪造挑战不能让账号进入冷却。冷却到期或成功验证后可恢复。
- **F3 部署说明已补充**：保持默认回环监听，并提供无需域名的 SSH 隧道步骤；HTTPS 代理需设置 Secure Cookie 与显式代理信任。没有连接实际服务器或为实际部署启用 TLS，见 [远程访问说明](docker.md#只有-ip-的远程访问)。

## 发现

### F1：内网来源可以伪造转发头绕开原 IP 冷却

等级：中。已复现。利用前提是客户端的直连地址被识别为回环或内网，或上游代理没有正确重写客户端转发头。

位置：`frontend/http-server.js:33`、`backend/management/auth.js:82`、`backend/management/auth.js:89`。

前端把所有内网和回环对端视为可信代理，从 `X-Forwarded-For` 或 `X-Real-IP` 取客户端地址，再传给后端用于限流和审计。内网直连客户端因而可以自行提供这些头。

复现结果：同一真实连接来源，在 `X-Forwarded-For: 198.51.100.51` 下连续失败触发 `429`；改成 `198.51.100.52` 后立即恢复为 `401`，获得新的猜测机会。无需改变真实来源地址。相应审计来源也会被伪造。

密码和第二因素仍需正确，尚未复现通过这一问题直接取得管理会话。公网直接连接且没有经过受信任代理时，代码会忽略这些转发头；该风险不能概括为所有公网客户端均可伪造。

建议：明确配置可信代理地址或网段，默认不信任普通直连客户端的转发头；限制后端只能由前端代理访问。第二因素失败再增加账号维度的受控冷却，降低更换地址或分布式猜测的影响。

### F2：二次验证设置变化后，没有轮换当前会话令牌

等级：中，属于会话加固项。已复现。利用前提是攻击者已经拿到当前登录会话 Cookie。

位置：`backend/management/auth.js:201`，以及启用、关闭二次验证和更新恢复码的调用处。

`retainSession()` 清除其他会话，但保留当前会话键并更新它的账号验证标记，没有重新签发 Cookie。因此，用户启用 TOTP 后，攻击者持有的同一个 Cookie 副本也继续有效。

复现结果：保存启用前的 Cookie；正常确认 TOTP；启用响应没有 `Set-Cookie`；以旧 Cookie 访问 `/api/workspace` 仍返回 `200`。这是现有会话继续有效，不是未取得凭据的攻击者可以直接跳过 TOTP；也不能据此认为首次密码登录会绕过第二步。

建议：完成敏感认证设置变更后，使所有旧会话令牌失效，再为当前浏览器签发新的 Cookie 和 CSRF 值。客户端已有接收响应中 `csrf` 的机制，可以保持操作连续性。安全设置变化后的会话轮换依据见 [OWASP 会话管理建议](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html#renew-the-session-id-after-any-privilege-level-change)。

### F3：直接远程 HTTP 访问会暴露凭据和会话

等级：条件性高风险，属于部署项。已验证默认 HTTP 服务和 Cookie 配置；没有验证现有服务器实际上是否使用 HTTP。

位置：`compose.yaml:14`、`compose.yaml:37`、`backend/management/auth.js:147`、`backend/index.js`。

默认部署提供 HTTP，`PALBOX_SECURE_COOKIE` 为 `false`。如果把网页端口直接开放到公网或不可信网络并以 `http://IP` 访问，管理员密码、绑定密钥、动态码、恢复码和 Cookie 都缺少传输加密。会话 Cookie 一旦被截获，即可用于访问已登录的接口，TOTP 无法补足这条传输链路。

默认 Compose 仅绑定 `127.0.0.1`，不能把默认配置直接认定为已经公开暴露。通过加密隧道访问回环 HTTP 的情形也应与直接远程 HTTP 区分。

建议：远程使用 HTTPS 或加密隧道；HTTPS 部署时设置 `PALBOX_SECURE_COOKIE=true`，保证整个会话都经加密链路传输。只设置 Secure Cookie 本身不会为 HTTP 服务启用 TLS。[OWASP 传输与 Cookie 保护说明](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html#transport-layer-security)

## 本次未复现的问题

- 无密码或无第二因素登录：密码正确时只返回短期挑战，不签发完整会话；缺失、过期、伪造或已经使用的挑战受到拒绝。
- 动态码及恢复码重放：已用时间步持久化；恢复码原子消费，并发消费只允许一次成功。
- 修改二次验证绕过：相关接口需要完整登录、正确来源、CSRF；绑定还需重验密码和动态码，关闭或更新恢复码需密码与第二因素。
- 登录输入注入：SQL、NoSQL 对象、模板、Shell 和原型污染输入均未获得会话；登录路径没有把这些输入交给数据库查询、Shell 或动态脚本执行。
- 浏览器 XSS：真实用户名包含 HTML 和事件处理器时，登录日志及账号显示均作为文本处理，没有生成攻击节点或执行脚本。
- 普通接口及日志泄露：未登录访问受保护接口、伪造会话 Cookie 和直接请求数据文件均被拒绝；普通设置接口和登录、面板日志未返回 TOTP 密钥或恢复码；恢复码持久化只存摘要。
- 二维码向第三方泄露：二维码在浏览器本地编码；测试未观察到第三方请求。关闭账号弹窗后，绑定图片地址、密钥和输入框被清空。

TOTP 秘密保存在权限为 `0600` 的服务器配置文件中，这是本次确认的存储边界。如果同一运行用户或宿主机已经被控制，TOTP 不能防止读取该密钥。

## 补充：撤销中的写入、上传资源和本地备份路径

### 会话撤销后的待提交写入

原先工作空间、设置和任务入口只在读取请求体前认证。旧会话请求可以先通过认证，等待退出或 TOTP 轮换，再补完请求体；已进入设置或工作空间写队列的请求也可能在撤销后落盘。利用需要先有有效的会话及 CSRF，属于在途请求延续权限，不能据此认定未登录用户可写入。

已补充请求体读取后、队列执行时和原子替换前的授权检查。备份任务在异步存档预检查后再次验证；上传在接收、扫描后及元数据提交前验证，拒绝后清理暂存。已经接纳的管理任务继续执行，退出登录不承担中断游戏操作的职责。

### 已登录上传的资源限制缺口

原先单包压缩大小、解压大小和条目上限不足以限制并发上传、慢速上传及重复上传的暂存累计；tar 清单还要等进程完成后才检查条目和解压大小。利用需要完整登录与 CSRF，风险是占用后端连接、CPU、内存和磁盘。

已限制同一后端一次接收一个上传、读取时限 120 秒、暂存最多 5 份及总文件大小 8 GB。解压大小仍限 4 GB、条目限 20000；扫描改为流式检查清单，并统计 gzip 实际膨胀量（文件预算之外另留有界的 tar 头、填充和扩展元数据空间）。校验和解压使用超时及取消信号，失败后等待子进程和流结束并清理临时文件。已有暂存只在启动或后续上传时触发过期清理，当前上传不会被清理器移除。

### 需要本地目录写权限的备份父目录链接

完整备份 ID 的文本路径校验和下载的 `O_NOFOLLOW` 只约束最终文件，不能阻止本地写入者把 `backups` 或分类目录替换成符号链接。原先删除接口检查了父目录，但下载、列表、恢复、创建及保留清理未统一检查。此问题需要本地数据目录写权限；HTTP 接口不提供创建这些链接的能力，不能描述为仅凭远程请求即可任意读取文件。

现已统一检查备份根目录和分类目录，覆盖初始化、创建、列表、下载、恢复、删除、保留清理和官方备份临时目录；创建归档使用独立随机临时目录。数据根目录仍受信任，逐级检查不能保证抵御本地写入者在检查后并发替换目录；具有同一运行用户权限的进程也能直接修改数据和账号文件。这次加固不声称建立了新的本地权限隔离边界。
