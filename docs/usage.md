# 使用指南

[返回 README](../README.md)

Palbox 提供一个需要登录的管理网页，分为游戏管理和配置管理；有效配置统一保存到服务器。首次访问时先在页面中创建管理员用户名和至少 12 位密码，之后使用该账号登录。

## 账号安全与二次验证

侧栏底部的「账号」可启用 TOTP 二次验证，默认关闭，已有账号无需重新初始化。输入管理员密码后，用验证器扫描二维码，或手动添加账号、选择「基于时间」并输入显示的密钥；使用 6 位动态验证码完成绑定。只有验证成功后才会启用，关闭弹窗不会开启未完成的绑定。

启用后，登录分两步：先输入管理员用户名和密码，再输入验证器的动态验证码。验证码每 30 秒更新，已成功使用的验证码不能重复使用；若提示已使用，请等待下一组。密码通过时尚未建立登录会话。服务器与手机都应保持时间同步。

启用后一次性显示 10 个恢复码，请另行保存。手机丢失时，在二次验证登录页点击「使用恢复码」，输入其中一个恢复码；每个只能使用一次。登录后可在「账号」中重新生成恢复码，旧码立即失效。重新生成或关闭二次验证均需管理员密码和当前动态验证码或有效恢复码。绑定、关闭或更新恢复码后，其他设备需重新登录。

TOTP 无需域名，可通过 IP 地址使用；远程访问仍应通过 HTTPS 或 SSH 隧道保护密码、绑定密钥与登录会话。密钥保存在服务器 `palbox/settings.json` 的管理员记录中，文件权限为仅运行用户可读写；恢复码仅保存摘要，普通设置接口和日志不会返回或记录这些秘密。

## 新建与导入

- 默认配置读取数据目录中 `server/DefaultPalWorldSettings.ini` 的官方文件，新建时重新读取，使用当前安装版本的参数与顺序，保留注释和未知参数。面板仅设置管理必需的 `RESTAPIEnabled`、管理员密码和游戏公布端口。
- 全新部署只显示「游戏默认配置」入口，不自动创建「我的帕鲁世界」或占位配置。未检测到官方默认文件时入口为灰色、不可选择；安装完成或检测到有效文件后自动启用。用户也可手动新建或导入独立配置。已有 `PalWorldSettings.ini` 会保留为「当前游戏配置」，已有配置库继续沿用。
- 官方默认文件不存在时，点击「新建配置」会创建仅含 REST API、随机管理员密码和公布端口的独立配置，可自行编辑或粘贴源码；不会写入游戏默认文件。官方默认文件内容无效时明确提示错误。
- 安装服务端后，配置库会保留一条「游戏默认配置」：以游戏目录中的 `DefaultPalWorldSettings.ini` 作为输入来源，名称和来源固定，输入源码只读；面板会为它自动生成管理员密码，并补入启用的 REST API 和公布端口，可直接选择、修改参数并应用。自动生成的密码会跨文件和面板重启保留，也可在参数中查看或修改。未修改参数时会随官方文件更新；修改后保留参数，仅更新「恢复原始」的基准。面板启动、安装或更新服务端、读取配置库以及状态轮询时会重新读取该文件。面板不会写入 `DefaultPalWorldSettings.ini`；编辑默认条目和应用配置只修改面板配置库与游戏实际配置 `PalWorldSettings.ini`。只有 SteamCMD 安装/更新服务端或手动修改时该文件才会变化。
- 可导入 `.ini` 文件，或粘贴包含 `OptionSettings=(...)` 的源码。每次导入创建独立配置，不会自动补入模板中的缺失字段。
- 支持新建、重命名、复制和删除配置。副本与原配置独立；新建配置从当前官方默认文件生成，来源标为“基于官方默认配置”。

## 编辑参数

分类表单与「高级编辑」均可修改参数。参数同时显示原始名称和中文名称，可使用搜索框或按 `/` 搜索。

| 状态 | 含义 |
| --- | --- |
| 官方说明 | 有官方文档明确说明的参数 |
| 未验证 | 使用社区解释的参数 |
| 未识别参数 | 尚未收录用途说明的字段 |

悬浮在说明铭牌上可查看用途。参数数量取决于当前游戏版本的默认文件和导入内容，说明目录区分官方用途说明和社区解释。来源保留在 [参数明细](parameters.md) 中，页面不展示来源链接。

点击顶部「未识别参数」统计卡片，或开启「仅显示未识别参数」，可以集中编辑未知字段。「仅显示未验证参数」用于筛选社区解释项。两种状态筛选互斥，可分别配合搜索使用。

搜索、分类和筛选不改变参数原始顺序、实际值或复制内容。原始文本值需要双引号，布尔值使用 `True` / `False`。

### 源码编辑

在「高级编辑 → 输入源码」中粘贴或编辑 INI，点击「应用源码」后同步到表单和输出，并自动保存。「游戏默认配置」的输入源码只读，不能直接粘贴或应用；请使用可视化编辑或参数列表修改参数。

「输出源码」只读展示当前生效的完整 INI，支持一键复制。未应用的输入和非法修改不会进入输出；切换输入与输出会保留输入草稿。解析失败时保留现有配置。

解析器拒绝重复目标段落、重复目标配置项、重复参数，以及未闭合的引号和括号。新版本未知参数和枚举可保留；导入时不强制重写旧配置，修改已知字段时才进行对应验证。

### 数值格式

显示、输出和复制共用小数格式，例如 `2` → `2.000000`、`2.5` → `2.500000`。更多小数位保留精度，整数参数和未知字段保留原样。

表单与参数列表加载时显示补齐后的值；输入期间保持光标位置，点击其他位置或按 Tab 离开输入框后补齐，并同步到当前编辑值。单纯查看已有配置不会产生修改。

## 保存与恢复

表单和参数列表的有效修改会自动保存，不会打断输入或重置光标。未应用源码和非法输入保留为当前页面草稿，不会写入已保存配置。

可视化编辑和参数列表中，偏离这套配置最初输入值的参数显示「已修改」铭牌，包括未识别参数。有效修改保存后，刷新或切换配置仍保留标记；改回原值或恢复输入配置后，相应标记消失。数字仅补齐小数位不算修改，尚未应用的源码和非法输入仍按草稿处理。

「已修改参数」区域汇总相对初始输入的修改项，并显示保存状态，悬浮可查看完整说明：

| 状态 | 含义 |
| --- | --- |
| 已保存 | 当前有效配置已存入对应存储 |
| 待应用 | 输入源码尚未应用到当前配置 |
| 输入有误 | 存在需要修正的输入 |
| 保存失败 | 存储失败，编辑结果仍保留在页面中 |

提交服务器时还会显示「保存中」。顶部操作栏集中显示游戏配置状态与「应用配置」按钮，服务运行时按钮显示「应用并重启」；可视化编辑和高级编辑共用，配置列表中隐藏应用入口。配置存盘与写入游戏是两个操作，游戏配置的「待生效」「已写入」「已生效」状态见 [Docker 部署文档](docker.md#配置与生效)。

保存失败时可先复制配置备份，按 `Ctrl/Cmd + S` 手动重试。切换配置时，如果仍有未应用源码、非法输入或保存失败的修改，会提示放弃或取消。

### 恢复输入配置

点击顶部配置工具中的「恢复原始」，确认后将当前配置恢复为最初输入或导入的完整内容，包含原始参数、未知字段、注释和顺序，并自动保存。「导入」用于导入文件或粘贴配置，「复制 INI」将当前完整配置复制到剪贴板；右上角「退出」用于退出登录。

取消确认不会改变编辑。启用此功能前已有的配置，以当时已保存的内容为恢复基准；复制的配置以复制时的内容为独立基准。

### 数据保存

配置保存在服务器数据目录的 `palbox/workspace.json`，存档和备份也保存在服务器。换浏览器或清除网站数据不会删除这些文件。服务器保存失败时，编辑结果仍保留在页面中，可先复制配置备份，再重试保存。配置文件与输出源码包含游戏配置中填写的明文密码。

## 登录日志

左侧「登录日志」是独立入口，显示登录成功、失败及尝试过于频繁的记录，包含 UTC 时间和来源 IP，失败记录还包含尝试的用户名，不记录密码。记录实时刷新，断线自动重连；向上滚动可查看历史。登录日志与游戏运行、安装更新和面板任务日志分开保存和展示。首次升级会保留旧面板日志最近 64 KB 中可识别的登录记录。

## 游戏与存档管理

登录后默认进入「游戏管理 → 服务器概况」。所有页面共用顶部游戏服务操作栏，不显示路径文字；「游戏服务」、状态铭牌、自动启动、任务记录和安装、启停、更新、参数设置等按钮在同一行排列，空间不足时自动换行。配置编辑与配置列表的顶部工具也同行排列，不强制另起一行；空间不足时自动换行。未安装时显示安装按钮，停服时显示启动，运行时显示停止和重启。服务状态仅通过铭牌显示，不展示额外状态说明或「任务已开始」等任务提示；任务进度和结果在「任务记录」弹窗中查看，失败时通过气泡提示。正文按游戏版本、在线人数、FPS、游戏端口、运行时间的顺序展示运行信息，Steam Build 显示在版本下方，小屏幕自动换行。运行日志位于信息栏下方，高度随窗口调整，日志较多时在窗口内滚动。操作栏末尾的「任务记录」按钮打开弹窗，显示近期任务的时间、状态与详细信息，点击关闭或按 Esc 返回；编辑配置通过侧栏「配置管理」进入。

在顶部「游戏服务」操作栏点击「启动参数」按钮，可在弹出窗口中编辑：每行一个参数，保存到服务器设置中，不会自动重启游戏服，将在下次启动或重启时生效。`-port` 由面板的 `PALBOX_GAME_PORT` 管理，不能在启动参数中填写。游戏运行时点击「运行参数」可以查看当前进程实际使用的启动命令、只读运行配置，以及运行配置是否与面板当前配置一致；停服时该按钮不可用。

「安装参数」按钮会显示当前完整的 SteamCMD 参数，每行一项，可在网页中编辑，保存后下次安装或更新服务端时生效。`+force_install_dir` 必须保持为面板的安装目录，`+app_update` 固定为 `2394010`，最后一项必须是 `+quit`；其余参数（例如 `validate`、`-beta public`）可以自定义。

「游戏管理」下设「服务器概况」「玩家管理」两个二级菜单。全局顶部栏的「游戏服务」后可切换「自动启动」滑块；启用后面板启动时会自动创建启动任务，默认关闭。正文展示实时日志，可按来源筛选；点击顶部「任务记录」可在弹窗中查看近期管理任务。玩家管理提供在线列表、广播、移出、封禁与解封。名单来自游戏当前的本服封禁记录，停服时可查看；游戏管理接口就绪且无任务执行时才可解封，读取失败会明确提示。

「存档管理」独立为导航分组，下设「官方备份」「手动备份」两个二级菜单。官方页面提供保存世界、导入存档、官方快照列表、下载和恢复；手动页面提供创建完整备份、归档下载／恢复／删除和保留数量设置。两页分别显示备份数量与总大小，切换时只加载当前类别的列表。刷新页面或浏览器前进后退时保留当前子页面，手机端可从左上角菜单进入；旧地址 `#game/saves` 仍可打开官方备份页面。

服务器概况的「游戏版本」卡片右侧提供「检查更新」，结果在页面顶部以大气泡显示；它优先通过 SteamCMD.net API 查询 Steam 上的最新 build，失败时回退 SteamCMD，与本地 `steamapps/appmanifest_2394010.acf` 对比，显示是否可更新。操作栏中保留运行/启动/安装参数、关服设置、更新服务端和「强制停止」（正常停止失败时使用）。

「关服设置」中可同时设置等待秒数（0–300 秒）和关服提示文字（1–500 个字符），默认提示为「Palbox 正在维护服务器」。保存后，下次正常停止、重启或维护停服时会使用该提示；强制停止不使用倒计时和提示。

「游戏版本」显示游戏管理接口返回的版本号，同时显示本地 Steam Build。停服或接口短暂不可用时保留本次面板运行期间已读取的版本号，检测到 Build 变化后清除旧版本；尚未读取到游戏版本时显示「启动后获取」，本地 Build 仍可查看。

「存档管理 → 官方备份」支持「导入存档」：上传 `.tar.gz` / `.tgz` 官方存档压缩包后会立即保存世界、停服、创建恢复前完整备份并替换当前世界/玩家存档，完成后按原状态启动。支持快照根目录、`SaveGames/0/<世界 ID>` 和 `Pal/Saved/SaveGames/0/<世界 ID>` 布局；只导入世界 `.sav` 与 `Players`，配置文件和官方备份历史保持不变。压缩包最多 1 GB，且只能包含一个世界；如果压缩包没有 `Players`，现有玩家存档会保留。

同一后端一次接收一个存档上传；读取上传内容限时 120 秒。默认解压文件总量最多 4 GB、归档最多 20000 个条目；暂存最多 5 份，总文件大小最多 8 GB（包括处理中的压缩包和解压文件）。超限请求会被拒绝，失败上传会清理；已有暂存可在导入后释放，或在过期后由下次上传／服务启动清理。

「配置管理」使用二级菜单：「配置编辑」「配置列表」。配置编辑页顶部可在「可视化编辑」和「高级编辑」之间切换；「高级编辑」内再选择参数列表、输入源码或输出源码。配置列表集中展示已保存的配置，不显示概况信息卡；每个条目提供选择、重命名、创建副本和删除按钮，无需先选中配置，管理条目后仍停留在列表中。管理其他配置不会切换当前配置或丢弃编辑中的草稿；删除当前配置时会确认未保存的更改。存在「游戏默认配置」时，删除最后一个可编辑配置后只保留该默认条目并切换过去；删除最后一条普通配置后配置库可保持为空，不自动补建配置。点击条目名称会弹出该配置的输入源码和来源，不会切换当前配置；普通配置的源码可直接编辑并保存。「游戏默认配置」在弹窗中仅可查看和复制，保存按钮隐藏，输入源码只读且以游戏目录中的 `DefaultPalWorldSettings.ini` 为来源；名称和来源不可改，也不能删除，但可以「选择」后进入参数表单，在「可视化编辑」或「参数列表」中修改参数并应用。未修改参数时会随官方文件更新，修改后保留参数，可用「恢复原始」回到当前官方默认。点击其他条目的「选择」切换配置并进入配置编辑（直接显示输入源码，可再切换回可视化编辑）。来源会标注为官方默认配置（游戏默认来源）、基于官方默认配置、当前游戏配置、导入文件、粘贴导入、复制自某配置或手动创建的配置；旧配置没有来源记录时显示“已有配置”。旧版来源为官方默认配置的普通配置会迁移为“基于官方默认配置”，仍可编辑；官方来源只保留给该服务端条目。列表条目也会直接显示来源。编辑页保留导入、恢复输入、复制与应用配置。

游戏管理和配置管理使用相同的选择方式：点击一级入口进入首个二级页，二级菜单高亮当前页面；切换保留编辑草稿，刷新和浏览器前进后退保留当前页面。手机端从左上角打开菜单，选择后自动收起。

在「配置管理」顶部点击「应用配置」，由管理后端完成校验、备份、写入，并按需重启游戏。仅保存面板配置不会直接修改游戏文件。「待生效」「已写入」「已生效」显示在配置应用区；任务详情在「游戏管理 → 服务器概况 → 任务记录」中查看，失败时显示错误提示。操作流程与存档管理见 [Docker 部署文档](docker.md)。

### 官方自动备份与完整备份

官方自动备份由游戏的 `bIsUseBackupSaveData=True` 控制，游戏运行时自行生成，面板不会为自动备份停止服务器。默认按 30 秒、10 分钟、1 小时、1 天档位轮换，当前版本的默认保留数量分别约为 5、6、12、7 份；具体间隔和数量由游戏版本决定，面板只读取，不修改这些档位。默认模板已开启；已有配置可在「配置管理」中搜索「自动备份世界」，修改后应用到游戏。

「存档管理 → 官方备份」显示游戏自动生成的快照，「存档管理 → 手动备份」显示完整备份归档（含手动、更新前和旧定时归档）。官方备份从 `Pal/Saved/SaveGames/0/<世界 ID>/backup/world/<时间>/` 读取，包含世界和玩家存档；只有内容完整且不含链接的备份才会列出。每页显示 10 份，可翻页查看全部；面板不清理官方备份。下载会先复制并检查文件是否发生变化，再打包，不停止游戏；仍在写入或已轮换的备份需刷新后重试。

恢复官方备份需要确认当前世界：优先使用 `GameUserSettings.ini` 的 `DedicatedServerName`，未指定时仅在只有一个世界目录的情况下允许恢复。面板先准备备份副本，再保存并停服、创建当前数据的完整备份，最后替换对应世界和玩家存档；保留当前游戏配置及官方备份历史，原先运行的游戏会重新启动。恢复前处于停止状态时，不会自动启动。

「创建完整备份」仍会短暂停服，将整个 `Pal/Saved` 打包，适合人工归档和更新前保护。手动备份必须存在非空的世界主存档 `SaveGames/0/<世界 ID>/Level.sav`；目录不存在、空目录或只有配置文件时不允许手动备份，也不会显示备份成功。停服且无世界存档时按钮禁用，已有归档仍可下载或恢复。旧面板的定时停服备份计划在升级时自动移除；已有定时归档仍可下载和恢复，面板的保留数量仅作用于完整备份，不清理官方备份。

完整备份归档的每条记录提供「下载」「恢复」「删除」。删除需确认，仅移除所选归档文件，不停服，也不改变当前游戏存档；删除后列表数量和总大小自动更新。删除与其他管理任务串行执行，任务进行中不可删除归档。手动、更新前和旧定时归档均支持删除，官方自动备份仍由游戏管理。
