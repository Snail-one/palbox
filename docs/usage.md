# 使用指南

[返回 README](../README.md)

Palbox 提供一个需要登录的管理网页，分为游戏管理和配置管理；有效配置统一保存到服务器。首次访问时先在页面中创建管理员用户名和至少 12 位密码，之后使用该账号登录。

## 账号安全与二次验证

侧栏「账号」会显示当前登录用户名，可通过「修改用户名」设置新的 1–64 位名称，首尾空白会自动去除。保存时需要当前密码，已启用二次验证时还需要动态验证码或恢复码。修改成功后当前浏览器继续保持登录，其他设备和未完成的登录验证失效，需要使用新用户名重新登录；原密码、游戏配置和存档保持不变。验证器绑定与未使用的恢复码保留，验证器里原有的账号显示名称不影响动态码，可自行改名。

侧栏底部的「账号」可启用 TOTP 二次验证，默认关闭，已有账号无需重新初始化。输入管理员密码后，用验证器扫描二维码，或手动添加账号、选择「基于时间」并输入显示的密钥；使用 6 位动态验证码完成绑定。只有验证成功后才会启用，关闭弹窗不会开启未完成的绑定。

启用后，登录分两步：先输入管理员用户名和密码，再输入验证器的动态验证码。验证码每 30 秒更新，已成功使用的验证码不能重复使用；若提示已使用，请等待下一组。密码通过时尚未建立登录会话。服务器与手机都应保持时间同步。

启用后一次性显示 10 个恢复码，请另行保存。手机丢失时，在二次验证登录页点击「使用恢复码」，输入其中一个恢复码；每个只能使用一次。登录后可在「账号」中重新生成恢复码，旧码立即失效。重新生成或关闭二次验证均需管理员密码和当前动态验证码或有效恢复码。绑定、关闭或更新恢复码后，其他设备需重新登录。

TOTP 无需域名，可通过 IP 地址使用；远程访问仍应通过 HTTPS 或 SSH 隧道保护密码、绑定密钥与登录会话。密钥保存在服务器 `palbox/settings.json` 的管理员记录中，文件权限为仅运行用户可读写；恢复码仅保存摘要，普通设置接口和日志不会返回或记录这些秘密。

## 新建与导入

- 默认配置读取数据目录中 `server/DefaultPalWorldSettings.ini` 的官方文件，新建时重新读取，使用当前安装版本的参数与顺序，保留注释和未知参数。面板仅设置管理必需的 `RESTAPIEnabled`、管理员密码和游戏公布端口。
- 全新部署只显示「游戏默认配置」入口，不自动创建「我的帕鲁世界」或占位配置。未检测到官方默认文件时入口为灰色、不可选择；安装完成或检测到有效文件后自动启用。用户也可手动新建独立配置；导入配置需要先安装服务端并生成官方默认文件。已有 `PalWorldSettings.ini` 会保留为「当前游戏配置」，已有配置库继续沿用。
- 官方默认文件不存在时，点击「新建配置」会创建仅含 REST API、随机管理员密码和公布端口的独立配置，输入源码只读，可在参数表单中修改；不会写入游戏默认文件。官方默认文件内容无效时明确提示错误。
- 安装服务端后，配置库会保留一条「游戏默认配置」：以游戏目录中的 `DefaultPalWorldSettings.ini` 作为输入来源，名称和来源固定，输入源码只读；面板会为它自动生成管理员密码，并补入启用的 REST API 和公布端口，可直接选择、修改参数并应用。自动生成的密码会跨文件和面板重启保留，也可在参数中查看或修改。官方文件更新后，新增参数自动补入，未修改的参数跟随新默认值，已修改的参数保留；「恢复原始」的基准也同步更新。更新面板配置后，仍需点击「应用配置」才会写入游戏。面板启动、安装或更新服务端、读取配置库以及按需读取状态时会重新读取该文件。面板不会写入 `DefaultPalWorldSettings.ini`；编辑默认条目和应用配置只修改面板配置库与游戏实际配置 `PalWorldSettings.ini`。只有 SteamCMD 安装/更新服务端或手动修改时该文件才会变化。
- 每套配置的恢复基准都是当前官方默认文件补入管理项后的内容，与「游戏默认配置」相同。未改过的配置会随官方文件更新；改过的配置保留已改参数，并补上官方文件新增的参数。输入源码一律只读，不能直接粘贴或改写。
- 可导入 `.ini` 文件，或粘贴包含 `OptionSettings=(...)` 的源码。每次导入以当前官方默认配置为底覆盖导入的同名参数，缺项沿用默认值，导入独有的未知参数追加保留，并创建独立配置，不修改已有配置。无论导入内容如何设置，REST API 都会打开，管理员密码使用「游戏默认配置」已有的随机密码。默认文件不存在或无效时提示错误，保留导入内容供重试。导入值与官方默认的差异直接显示为“已修改”。
- 支持新建、重命名、复制和删除配置。副本与原配置独立；新建配置从当前官方默认文件生成，来源标为“基于官方默认配置”。

## 编辑参数

分类表单与「高级编辑」均可修改参数。参数同时显示原始名称和中文名称，可使用搜索框或按 `/` 搜索。

| 状态 | 含义 |
| --- | --- |
| 官方说明 | 有官方文档明确说明的参数 |
| 未验证 | 使用社区解释的参数 |
| 未识别参数 | 尚未收录用途说明的字段 |

悬浮在说明铭牌上可查看用途。参数数量取决于当前游戏版本的默认文件和导入内容，说明目录区分官方用途说明和社区解释。来源保留在 [参数明细](parameters.md) 中，页面不展示来源链接。

点击顶部「未识别参数」统计卡片，或开启「仅显示未识别参数」，可以集中编辑未知字段。「仅显示未验证参数」用于筛选社区解释项。两种状态筛选互斥，可分别配合搜索使用。

搜索、分类和筛选不改变参数原始顺序、实际值或复制内容。原始文本值需要双引号，布尔值使用 `True` / `False`。

### 源码编辑

「高级编辑 → 输入源码」只读，所有配置都不能直接修改源码。请使用可视化编辑、参数列表，或在配置列表中点击该条目后选择「导入配置」。底层读取官方默认配置 `DefaultPalWorldSettings.ini`。

「输出源码」只读展示当前生效的完整 INI，支持一键复制。未应用的输入和非法修改不会进入输出；切换输入与输出会保留输入草稿。解析失败时保留现有配置。

解析器拒绝重复目标段落、重复目标配置项、重复参数，以及未闭合的引号和括号。新版本未知参数和枚举可保留；导入时保留参数原值，修改已知字段时才进行对应验证。

### 数值格式

显示、输出和复制共用小数格式，例如 `2` → `2.000000`、`2.5` → `2.500000`。更多小数位保留精度，整数参数和未知字段保留原样。

表单与参数列表加载时显示补齐后的值；输入期间保持光标位置，点击其他位置或按 Tab 离开输入框后补齐，并同步到当前编辑值。单纯查看已有配置不会产生修改。

## 保存与恢复

表单和参数列表的有效修改会自动保存，不会打断输入或重置光标；单行输入框中按回车可立即保存。输入源码只读，不能直接改写。非法输入保留为当前页面草稿，不会写入已保存配置。

可视化编辑和参数列表中，偏离这套配置初始基准的参数显示「已修改」铭牌，包括未识别参数。有效修改保存后，刷新或切换配置仍保留标记；改回原值或恢复输入配置后，相应标记消失。数字仅补齐小数位不算修改，尚未应用的源码和非法输入仍按草稿处理。

已修改的参数旁可点击「恢复默认」，二次确认后只恢复这一项到这套配置初始基准中的值（新导入配置为导入时的游戏默认值），并自动保存；取消时保留当前编辑。其他参数的修改和未完成输入保留；有输入错误的参数也可通过此按钮恢复。源码中新加的参数若没有初始值，不显示单项恢复按钮。恢复后仍需点击顶部「应用配置」让游戏使用新值。

「已修改参数」区域汇总相对初始基准的修改项，并显示保存状态，悬浮可查看完整说明：

| 状态 | 含义 |
| --- | --- |
| 已保存 | 当前有效配置已存入对应存储 |
| 待应用 | 输入源码尚未应用到当前配置 |
| 输入有误 | 存在需要修正的输入 |
| 保存失败 | 存储失败，编辑结果仍保留在页面中 |

提交服务器时还会显示「保存中」。顶部操作栏集中显示游戏配置状态与「应用配置」按钮，服务运行时按钮显示「应用并重启」；可视化编辑、高级编辑和配置列表共用。配置存盘与写入游戏是两个操作，游戏配置的「待生效」「已写入」「已生效」状态见 [Docker 部署文档](docker.md#配置与生效)。

保存失败时可先复制配置备份，按 `Ctrl/Cmd + S` 手动重试。切换配置时，如果仍有未应用源码、非法输入或保存失败的修改，会提示放弃或取消。

### 恢复输入配置

点击顶部配置工具中的「恢复原始」，确认后将当前配置恢复为初始基准，包含基准中的参数、未知字段、注释和顺序，并自动保存。已检测到官方默认文件时，每套配置都恢复到与「游戏默认配置」相同的官方默认；尚未安装时恢复为创建时的内容。「导入」用于导入文件或粘贴配置，「复制 INI」将当前完整配置复制到剪贴板；右上角「退出」用于退出登录。

取消确认不会改变编辑。安装前创建的配置以当时的内容为基准，检测到官方默认文件后改为该官方默认。

### 数据保存

配置保存在服务器数据目录的 `palbox/workspace.json`，存档和备份也保存在服务器。换浏览器或清除网站数据不会删除这些文件。服务器保存失败时，编辑结果仍保留在页面中，可先复制配置备份，再重试保存。配置文件与输出源码包含游戏配置中填写的明文密码。

## 登录日志

左侧「登录日志」是独立入口，显示登录成功、失败及尝试过于频繁的记录，包含时间和来源 IP，失败记录还包含尝试的用户名，不记录密码。记录按本地时间显示，最新记录在顶部；新记录实时追加，断线自动重连。向下滚动至底部或点击「加载更早日志」可继续读取磁盘上的历史；点击「返回最新」回到最近记录。登录日志与游戏运行、安装更新和面板任务日志分开保存和展示。首次升级会保留旧面板日志最近 64 KB 中可识别的登录记录。

运行日志和登录日志都会保留已加载内容，新的日志超过首次加载范围后，旧记录仍可阅读。浏览较多日志时会提示暂停实时更新，以保持页面响应；可继续查看更早记录，或点击「返回最新」恢复实时更新。磁盘上已被轮换覆盖或清理的记录无法再次加载，页面会提示历史缺口。「全部日志」使用 `game`、`update`、`PalBox` 标识游戏、安装更新和面板来源。运行日志保留所有有内容的记录，包括接口访问成功或失败、玩家进出及保存、关服等操作；显示时仅去掉空白行及只有时间和来源前缀的空行，原始日志文件中的空行保留。

## 游戏与存档管理

服务器状态按需读取，不再每 5 秒请求游戏接口：进入服务器概况读取 `info`、`metrics`、`players`；进入在线玩家页面只读取 `players`；打开「运行参数」才读取 `settings`。「刷新状态」仅更新当前页面所需的数据，相关操作完成后刷新一次。停留页面不会定时更新性能、在线人数或运行时间。任务进度与游戏进程退出通过服务端事件推送，日志继续实时推送；启动任务内保留有超时限制的接口就绪检查。玩家登录历史直接从游戏输出日志记录，不为历史增加游戏接口轮询。

登录后默认进入「游戏管理 → 服务器概况」。所有页面共用顶部游戏服务操作栏，不显示路径文字；「游戏服务」、状态铭牌、自动启动、自动代理、刷新状态、任务记录和安装、启停、更新、参数设置等按钮在同一行排列，空间不足时自动换行。配置编辑与配置列表的顶部工具也同行排列，不强制另起一行；空间不足时自动换行。未安装时显示安装按钮，停服时显示启动，运行时显示停止和重启。服务状态仅通过铭牌显示，不展示额外状态说明或「任务已开始」等任务提示；任务进度和结果在「任务记录」弹窗中查看，失败时通过气泡提示。正文按游戏版本、在线人数、FPS、游戏端口、运行时间的顺序展示运行信息，Steam Build 显示在版本下方，小屏幕自动换行。运行日志位于信息栏下方，高度随窗口调整，日志较多时在窗口内滚动。操作栏末尾的「任务记录」按钮打开弹窗，显示近期任务的时间、状态与详细信息，点击关闭或按 Esc 返回；编辑配置通过侧栏「配置管理」进入。

「存档管理 → 官方备份」中的「重置存档」仅在游戏服务器停止且没有任务执行时可用。点击后需要准确输入小写 `delete` 才能确认，后端也会校验确认文字与停服状态。确认后清空 `Pal/Saved/SaveGames/0/` 下的全部内容，包括世界、玩家和目录内的官方备份历史，保留 `0` 目录本身；游戏配置、该目录外的封禁名单及世界备份归档保留。重置前会先把当前世界目录和当时的 `PalWorldSettings.ini` 备份到独立的「重置前备份」分类，结构与世界备份相同；其他世界、日志、封禁名单和 `GameUserSettings.ini` 不进入这份备份。备份失败则中止清空；完成后保持停服，结果在「任务记录」查看；执行期间禁止提交启动及其他管理任务。

在顶部「游戏服务」操作栏点击「启动参数」按钮，可在弹出窗口中编辑：每行一个参数，保存到服务器设置中，不会自动重启游戏服，将在下次启动或重启时生效。`-port` 由面板的 `PALBOX_GAME_PORT` 管理，不能在启动参数中填写。游戏运行时点击「运行参数」可以查看当前进程使用的启动命令，以及游戏 REST API `/v1/api/settings` 返回的当前配置。默认以只读可视化面板展示，沿用配置编辑的分类、中文名称和说明，可按名称、说明或值搜索；开关显示开启或关闭状态，数值带单位，密码可通过输入框内的小眼睛查看。未知参数、空字符串、null、数组和对象也会保留，可切换「原始 JSON」核对完整返回值。每次打开都会重新读取，仅展示接口返回的字段，不补入默认值；搜索、分类和视图切换不会重新访问游戏。接口不可用时显示错误，不使用启动时的 INI 快照替代；停服时该按钮不可用。

「安装参数」按钮会显示当前完整的 SteamCMD 参数，每行一项，可在网页中编辑，保存后下次安装或更新服务端时生效。`+force_install_dir` 必须保持为面板的安装目录，`+app_update` 固定为 `2394010`，最后一项必须是 `+quit`；其余参数（例如 `validate`、`-beta public`）可以自定义。

「游戏管理」下设「服务器概况」「玩家管理」两个二级菜单。全局顶部栏的「游戏服务」后可切换「自动启动」和「自动代理」滑块。启用自动启动后面板启动时会自动创建启动任务，默认关闭。「自动代理」保存在 `autoProxy`，默认关闭；关闭时安装和更新服务端直连，开启后沿用面板进程环境中的代理，下次安装或更新时生效。正文展示实时日志，可按来源筛选；点击顶部「任务记录」可在弹窗中查看近期管理任务。玩家管理以卡片展示在线和已封禁玩家：在线卡片显示昵称、等级与 UserID，封禁卡片显示理由和时间，分别提供移出、封禁或解封操作；桌面双列、手机单列，全服广播有独立输入区。名单来自游戏当前的本服封禁记录，停服时可查看；广播和玩家操作需游戏管理接口就绪且无任务执行，读取失败会明确提示。

全服广播内容为空或只有空格时不可发送。发送期间输入框和按钮暂时禁用，按钮显示「发送中…」；广播任务成功后清空输入框并提示「广播已发送」，请求或任务失败时保留原文，显示失败原因，方便重试。

玩家管理顶部可切换「在线玩家」「登录历史」「封禁名单」，显示各自数量；切换保留历史搜索条件，支持方向键切换。卡片在桌面双列、手机单列。

「玩家管理 → 登录历史」直接解析游戏的 `connected the server. (User id: ...)` 日志，立即记录昵称、UserID、IP 和连接时间；同一 UserID 后续出现 `joined the server` 时标记「登录成功」，保留 IP。只有连接日志时显示「已连接」，重新连接会更新连接状态。历史按 UserID 汇总，显示首次连接、最近连接和已知的最近成功登录时间；可按昵称、UserID 或 IP 搜索，每页 10 位。接口访问日志及聊天内容不计入历史，不额外轮询游戏接口；关闭网页仍继续记录。启动时会回读保留的 `logs/game.log` 及轮换文件补全历史，已经删除的日志无法回溯。历史保存在数据目录的 `palbox/player-history.json`，重启、更新、导入或重置游戏存档后保留。玩家离线后也可从历史卡片填写理由并封禁；游戏服务必须就绪且没有任务执行，已封禁账号另有标记。停服时可查询历史。

「登录历史 → 清理历史」确认后清空全部玩家历史，包括当前搜索条件外的记录，保留游戏存档、封禁名单及原始日志。清理截止时间随历史文件保存，重启回读旧日志不会恢复已清理内容；之后新产生的连接和登录事件继续记录。

「恢复历史」会重新扫描仍保留的游戏日志及轮换文件，恢复被清理的玩家记录，并与当前历史按 UserID 合并；保留现有较新的昵称、IP、连接时间和登录状态。恢复成功后取消清理截止时间，重启也会继续回读保留的旧日志。已经轮换删除的原始日志无法恢复；该操作不修改游戏存档或封禁名单。

「存档管理」独立为导航分组，下设「官方备份」「世界备份」两个二级菜单。官方页面提供保存世界、导入存档、官方快照列表、下载和恢复；世界备份页面提供创建世界备份、归档下载／恢复／删除和保留数量设置，独立显示手动备份、恢复前备份、导入前备份和重置前备份。两页分别显示备份数量与总大小，切换时只加载当前类别的列表。刷新页面或浏览器前进后退时保留当前子页面，手机端可从左上角菜单进入；旧地址 `#game/saves` 仍可打开官方备份页面。

服务器概况的「游戏版本」卡片右侧提供「检查更新」，结果在页面顶部以大气泡显示；它优先通过 SteamCMD.net API 查询 Steam 上的最新 build，失败时回退 SteamCMD，与本地 `steamapps/appmanifest_2394010.acf` 对比，显示是否可更新。操作栏中保留运行/启动/安装参数、关服设置、更新服务端和「强制停止」（正常停止失败时使用）。

「更新服务端」仅在服务端已安装、游戏服停止且没有任务执行时可用；游戏运行中后端也会拒绝更新请求。更新直接执行 SteamCMD，不自动保存世界或创建备份，完成后保持停服，需要时手动启动。需要备份时可先手动创建世界备份。

「关服设置」中可同时设置等待秒数（0–300 秒）和关服提示文字（1–500 个字符），默认提示为「Palbox 正在维护服务器」。保存后，下次正常停止、重启或维护停服时会使用该提示；强制停止不使用倒计时和提示。

「游戏版本」显示游戏管理接口返回的版本号，同时显示本地 Steam Build。停服或接口短暂不可用时保留本次面板运行期间已读取的版本号，检测到 Build 变化后清除旧版本；尚未读取到游戏版本时显示「启动后获取」，本地 Build 仍可查看。

「存档管理 → 官方备份」的「导入存档」与备份恢复共用「导入与恢复」界面，选择文件后先上传并检测，展示检测到的存档、目标世界 ID 与目录，以及配置是否导入并选中「游戏默认配置」；用户确认后才执行恢复。旧格式完整存档包会在详情中明确显示整体替换 `Pal/Saved` 的范围。支持上传 `.tar.gz` / `.tgz` / `.zip` / `.7z` 世界存档或完整备份，最大 1 GB。`.zip` 和 `.7z` 需要服务器已安装 7zip。按包内目录和配置识别类型，不依赖文件名。完整备份支持 `Pal/Saved/`、`Saved/` 或直接包含 `Config/`、`SaveGames/` 的根目录，要求有非空的 `Config/LinuxServer/PalWorldSettings.ini`；包含世界时还需 `GameUserSettings.ini` 的 `DedicatedServerName` 指向包内有效世界。完整导入整体替换服务器的 `Pal/Saved/`，恢复包内配置、所有世界、玩家、官方备份历史、日志等全部内容，移除旧目录中包内不存在的内容，不依赖服务器原来的世界 ID。世界存档包支持快照根目录、`<世界 ID>/`、`SaveGames/0/<世界 ID>/` 和 `Pal/Saved/SaveGames/0/<世界 ID>/` 布局，必须包含非空的 `Level.sav`、`LevelMeta.sav`，且只能包含一个待导入世界；目标严格使用服务器当前 `GameUserSettings.ini` 的 `DedicatedServerName`，清空该世界目录后完整写入包内对应目录的全部文件和子目录。`Players/`、`backup/` 及其他内容在包内存在则写入，不存在则不保留旧内容；世界目录外的配置和其他世界保留。两类导入都会先校验，运行中则保存并停服，创建「导入前备份」后整体替换，失败时回滚目录；成功后原先运行则重新启动，原先停止则保持停止。包内若有 `PalWorldSettings.ini`，存档替换完成后按配置导入处理：以当前官方默认配置为底，补上缺项，再用包内同名参数覆盖，结果写入「游戏默认配置」并同步到游戏的 `PalWorldSettings.ini`。没有这份配置的世界包不改游戏配置。无论包内如何设置，REST API 都会打开，管理员密码沿用「游戏默认配置」已有的随机密码；还没有密码时会新生成一个。

同一后端一次接收一个存档上传；读取上传内容限时 120 秒。默认解压文件总量最多 4 GB、归档最多 20000 个条目；暂存最多 5 份，总文件大小最多 8 GB（包括处理中的压缩包和解压文件）。超限请求会被拒绝，失败上传会清理；已有暂存可在导入后释放，或在过期后由下次上传／服务启动清理。

「配置管理」使用二级菜单：「配置编辑」「配置列表」。配置编辑页顶部可在「可视化编辑」和「高级编辑」之间切换；「高级编辑」内再选择参数列表、输入源码或输出源码。配置列表集中展示已保存的配置，不显示概况信息卡；每个条目提供选择、重命名、创建副本和删除按钮，无需先选中配置，管理条目后仍停留在列表中。管理其他配置不会切换当前配置或丢弃编辑中的草稿；删除当前配置时会确认未保存的更改。存在「游戏默认配置」时，删除最后一个可编辑配置后只保留该默认条目并切换过去；删除最后一条普通配置后配置库可保持为空，不自动补建配置。点击条目名称会弹出窗口，可在「导入配置」和「查看源配置」之间切换，不会切换当前配置。导入配置把同名参数覆盖到这套配置，未包含的参数保持当前值；REST API 保持开启，管理员密码沿用这套配置已有的密码，没有密码时新生成一个，不采用导入内容中的这两项。查看源配置时，所有配置的输入源码都只读，只能查看和复制，保存按钮隐藏，底层为游戏目录中的 `DefaultPalWorldSettings.ini`。「游戏默认配置」的名称和来源不可改，也不能删除，可以点击「选择」设为当前配置，页面仍停留在列表；需要编辑时进入「配置编辑」，在「可视化编辑」或「参数列表」中修改参数并应用。未修改参数时会随官方文件更新，修改后保留参数，可用「恢复原始」回到当前官方默认。点击任意条目的「选择」只切换当前配置，不跳转页面。每套配置和当前配置概况都显示默认文件同步状态：「已同步最新默认配置」表示已基于当前官方默认补齐参数，自定义修改仍保留；「待同步最新默认配置」表示基准或参数尚未同步，可保存有效修改后刷新；默认文件缺失、不可读或尚未检测到时不会标记为最新。此状态与是否已应用到游戏分开显示。来源会标注为官方默认配置（游戏默认来源）、基于官方默认配置、当前游戏配置、导入文件、粘贴导入、复制自某配置或手动创建的配置；旧配置没有来源记录时显示“已有配置”。旧版来源为官方默认配置的普通配置会迁移为“基于官方默认配置”，仍可编辑；官方来源只保留给该服务端条目。列表条目也会直接显示来源。配置编辑和配置列表的顶部都保留导入、恢复输入、复制，以及游戏配置状态和「应用配置」。

游戏管理和配置管理使用相同的选择方式：点击一级入口进入首个二级页，二级菜单高亮当前页面；切换保留编辑草稿，刷新和浏览器前进后退保留当前页面。手机端从左上角打开菜单，选择后自动收起。

在「配置管理」顶部点击「应用配置」，由管理后端完成校验、写入，并按需保存世界、停服及重启游戏，不创建备份归档。仅保存面板配置不会直接修改游戏文件。「待生效」「已写入」「已生效」显示在配置应用区；任务详情在「游戏管理 → 服务器概况 → 任务记录」中查看，失败时显示错误提示。操作流程与存档管理见 [Docker 部署文档](docker.md)。

### 官方自动备份与世界备份

官方自动备份由游戏的 `bIsUseBackupSaveData=True` 控制，游戏运行时自行生成，面板不会为自动备份停止服务器。默认按 30 秒、10 分钟、1 小时、1 天档位轮换，当前版本的默认保留数量分别约为 5、6、12、7 份；具体间隔和数量由游戏版本决定，面板只读取，不修改这些档位。默认模板已开启；已有配置可在「配置管理」中搜索「自动备份世界」，修改后应用到游戏。

「存档管理 → 官方备份」以卡片显示游戏自动生成的快照，每张卡片展示时间、大小、所属世界及下载、恢复操作，并标记是否属于当前世界；宽屏每行三张、窄屏两列、手机单列。顶部汇总快照数量、总大小、最近备份时间和当前世界，并展示游戏默认保留策略。每页显示 10 份，可翻页查看全部。官方备份从 `Pal/Saved/SaveGames/0/<世界 ID>/backup/world/<时间>/` 读取，包含世界和玩家存档；只有内容完整且不含链接的备份才会列出，面板不清理官方备份。下载会先复制并检查快照和当前 `PalWorldSettings.ini` 是否发生变化，再打包，不停止游戏。压缩包内是 `<世界 ID>/` 下的世界和玩家存档，以及当时的 `Config/LinuxServer/PalWorldSettings.ini`。重新导入该压缩包时，世界存档仍按世界导入；包内的 `PalWorldSettings.ini` 会以官方默认为底补全缺项，合并进「游戏默认配置」并写入游戏。仍在写入或已轮换的备份需刷新后重试。

「存档管理 → 世界备份」按独立列表显示手动备份、恢复前备份、导入前备份和重置前备份，每组以独立卡片展示数量、大小及归档时间，每条备份显示保存时的世界 ID；无法从备份识别时显示“未识别”。桌面端双列、手机端单列。各分类每页完整显示 5 份，不限制内部滚动高度；底部提供上一页、页码和下一页按钮，各分类独立翻页，刷新列表时保留当前页，删除后当前页超出范围则回到最后一页。手机端操作按钮整行排列。页面顶部显示归档总量和最近备份时间。默认每类保留 5 份，各分类卡片可独立设置 1 到 20 份，修改后自动保存，按回车或移开焦点会立即保存；状态显示保存中、已保存或失败，失败保留输入并可回车重试，分类之间互不影响。

恢复官方备份严格使用服务器当前 `GameUserSettings.ini` 的 `DedicatedServerName` 确认世界，文件缺失或该值无效时禁止恢复，已有快照仍可下载。面板先准备备份副本，再保存并停服、创建当前数据的世界备份并归入「恢复前备份」，最后替换对应世界和玩家存档；保留当前游戏配置及官方备份历史，原先运行的游戏会重新启动。恢复前处于停止状态时，不会自动启动。

「创建世界备份」仅在游戏服停止且没有任务执行时可用。手动备份、恢复前、导入前和重置前备份都打包当前世界目录和当时的 `Config/LinuxServer/PalWorldSettings.ini`，结构与官方备份下载相同：`<世界 ID>/` 下放该世界目录里的全部文件，旁边是这份配置；不包含其他世界、`GameUserSettings.ini`、日志、封禁名单或游戏二进制。必须能确定当前世界，且该世界有非空的 `Level.sav`。手动备份在没有可读世界时拒绝。恢复前、导入前和重置前在没有可读世界、但已有 `PalWorldSettings.ini` 时只打包这份配置；`Pal/Saved` 为空时跳过。存在多个可读世界且无法确定当前世界时拒绝创建。游戏运行中拒绝手动备份，不自动停服或重启，完成后保持停服。各分类保留数量独立设置，不清理当前游戏维护的官方备份。

恢复世界备份时使用统一的「导入与恢复」界面，不再选择恢复方式。界面先检测存档和配置，显示来源世界 ID、当前游戏的目标世界 ID、实际恢复目录、配置处理和保护备份。确认后，世界内容清空并替换到当前 `GameUserSettings.ini` 的 `DedicatedServerName` 指定的目录，世界 ID 保持不变；其他世界、日志、封禁名单和 `GameUserSettings.ini` 保留。旧 `Pal/Saved` 归档也只提取来源世界和游戏配置。配置以官方默认为底补全后导入「游戏默认配置」，同步写入游戏并设为当前选中配置；REST API 保持开启，管理员密码沿用该配置已有的随机密码。配置缺失时保留现有配置；仅含配置的保护备份可以独立恢复。检测阶段不修改存档或配置。确认后若目标世界已改变会拒绝执行，要求重新检测；无法确认当前世界或来源世界时同样拒绝。恢复前先保存、停服并创建「恢复前备份」，完成后恢复原运行状态。接口不再需要 `mode`；旧客户端的 `mode: "world"` 继续按当前世界恢复，`mode: "full"` 已移除。

世界备份归档的每条记录提供「下载」「恢复」「删除」。删除需确认，仅移除所选归档文件，不停服，也不改变当前游戏存档；删除后列表数量和总大小自动更新。删除与其他管理任务串行执行，任务进行中不可删除归档。手动、恢复前、导入前和重置前备份均支持删除，官方自动备份仍由游戏管理。

### 时间与时区

服务端和游戏进程统一使用 UTC，接口时间携带 `Z` 标记，磁盘日志保留 UTC 原始时间。网页根据用户电脑的时区显示备份、任务、封禁和登录时间；运行日志保留毫秒，并显示本地 UTC 偏移量，自动处理夏令时和跨日。官方备份的 UTC 目录名保留用于定位，页面和从网页下载的所有备份文件名使用用户电脑的本地时间。下载文件统一命名为 `时间-属性-世界ID.tar.gz`，时间格式为 `YYYY.MM.DD-HH.mm.ss`，官方备份属性为 `pal`，所有分类的世界备份属性为 `Full World`；世界 ID 使用备份自身的世界，无法识别时写为 `unknown`。两个下载接口均可传入 `timeZone` 时区，未传入时默认使用 UTC。修改电脑时区后刷新网页生效。
