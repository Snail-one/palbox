# Palbox · 帕鲁配置工作台

中文、纯浏览器运行的 `PalWorldSettings.ini` 编辑器。支持多配置本地保存、常用参数表单、全部参数搜索与编辑、INI 源码编辑，以及文件选择、拖放和粘贴导入。

## 运行

使用 Node.js 22 或以上版本启动，无需安装依赖或构建：

```sh
npm start
```

访问 <http://127.0.0.1:8080>，按 `Ctrl+C` 停止。也可直接运行 `node server/index.js`。默认仅监听本机，修改端口可使用 `PORT=8081 npm start`（Linux/macOS）。

Node.js 使用内置 HTTP 模块提供页面和静态资源；所有配置编辑与存储仍在浏览器中完成。无需 Python 或第三方运行依赖。前端使用原生 ES Modules，请通过 HTTP 访问，不要直接双击 HTML 文件。推荐保持访问地址固定，让本地存储的来源保持稳定。

## 使用

1. 首次打开时创建「我的帕鲁世界」，使用本项目用户提供的完整 122 项参数模板。该模板是一个固定版本快照，不会联网自动更新。
2. 导入 `.ini` 文件或直接粘贴 `OptionSettings=(...)`。每次导入创建独立配置，不会补入缺失字段。
3. 分类表单与「高级编辑」均可修改参数。所有参数以原始参数名、中文名称两行展示。官方明确说明的参数显示「官方说明」铭牌，社区解释显示「未验证」铭牌，鼠标悬浮铭牌显示详细说明；页面不展示来源链接。当前 122 项中，99 项有官方说明、23 项使用社区解释，其中 11 项集中在「高级设置」（详见 [参数明细](docs/parameters.md)）。未收录用途的新字段计入「未识别参数」，点击顶部统计卡片或使用「仅显示未识别参数」滑动开关可集中编辑；「仅显示未验证参数」开关筛选社区解释项。两个状态筛选互斥，都可以配合搜索使用。所有统计、搜索和筛选都不改变复制内容、原始值与参数顺序。文本原始值需要双引号，布尔值使用 `True` / `False`。
4. 「高级编辑 → 输入源码」用于粘贴和编辑 INI，点击「应用源码」后同步到表单和输出，再保存。「输出源码」只读展示当前生效的完整 INI，支持一键复制；未应用的输入和无效修改不会包含在输出中，切换输入与输出会保留输入草稿。解析失败保留现有配置；源码中的密码会以明文呈现。
5. 顶部导入、保存和复制按钮随页面滚动保持可见。点击「保存配置」保存到当前浏览器，或按 `Ctrl/Cmd + S`。按 `/` 可搜索参数。
6. 点击橙色「复制配置」按钮，直接将完整 INI 内容复制到剪贴板，包含当前有效编辑结果。复制不会自动保存浏览器内的修改；源码修改需先应用。复制后可粘贴到服务器配置文件中，或自行保存为 INI 文件备份。

新建、重命名、复制和删除配置均在浏览器内进行。复制使用当前有效编辑结果，原配置保留其上一次保存的内容。切换配置时若有未保存修改，会提示放弃或取消。

数据保存在当前浏览器、当前网站来源的 `localStorage` 中，不会上传。端口、域名、协议或浏览器不同，工作空间也不同；直接打开本地文件时的存储行为取决于浏览器。配置文件和本地存储都包含配置中填写的密码。建议复制各配置并保存为文件备份；清除网站数据会删除本地记录。

若本地存储被禁用或空间不足，页面显示失败信息，当前配置仍可复制。若已有本地数据损坏，页面保留原始数据、阻止覆盖，并提供临时工作空间。可先从开发者工具备份 `palbox.workspace.v1` 的原始值，再修复或移除该键并重新导入备份配置。

## 应用到帕鲁服务器

先备份服务器原配置，再将复制的内容写入对应目录中的配置文件，并重启服务器：

- Linux：`Pal/Saved/Config/LinuxServer/PalWorldSettings.ini`
- Windows：`Pal/Saved/Config/WindowsServer/PalWorldSettings.ini`

修改 `DefaultPalWorldSettings.ini` 不会直接更新运行配置。参数行为与版本差异以 [帕鲁官方配置文档](https://docs.palworldgame.com/settings-and-operation/configuration/) 为准；本工具不连接服务器，也不修改存档或 Mod 配置。

## 项目结构

```text
public/                  页面、图标和按职责拆分的样式
src/
  main.js                浏览器入口，创建并注入依赖
  app.js                 组装应用，连接界面和服务
  domain/                配置解析、参数目录、模板和编辑状态
  application/           工作空间操作与持久化协调
  services/              浏览器存储、剪贴板和文件读取适配器
  ui/                    页面组件、弹窗和导航
server/                  Node.js 启动入口与静态 HTTP 服务
  index.js
  http-server.js
tests/
  unit/                  领域规则、服务与架构约束测试
  integration/           HTTP 服务测试
  e2e/                   Playwright 浏览器回归
  shared/                Node.js 与浏览器共用的配置测试用例
  browser/               浏览器中的配置测试页面
docs/architecture.md    模块职责、依赖方向和扩展说明
```

模块使用 ES Modules，通过 `import` / `export` 明确依赖，不再使用 `window.Pal*` 全局命名空间或依赖脚本加载顺序。领域层可直接在 Node.js 中测试，存储、剪贴板和文件实现通过入口注入。详细设计见 [架构说明](docs/architecture.md)。

样式入口为 `public/styles/index.css`，设计变量统一放在 `tokens.css`，其余按布局、控件、编辑器、弹窗和响应式规则组织。历史重复声明已整理，外观沿用浅灰背景、黑色文字、橙色重点。

解析器拒绝重复目标段落、重复目标配置项、重复参数以及未闭合的引号和括号。新版本的未知参数和枚举可保留；导入不强制重写旧配置，修改已知字段时才进行对应验证。

## 开发与验证

运行开发服务（服务端文件变动后自动重启，前端文件修改后刷新页面即可）：

```sh
npm run dev
```

核心功能和服务端只使用 Node.js 内置模块，运行和普通测试不需要安装第三方依赖：

```sh
npm test
npm run test:unit
npm run test:integration
```

测试覆盖完整模板往返、注释与顺序保留、嵌套列表、空值、未知字段、编辑与源码草稿隔离、保存失败回滚、已有 v1 存储兼容和 HTTP 资源访问。架构测试会检查循环依赖和领域／应用／服务／界面层之间的依赖方向。在浏览器访问 `/tests/index.html` 也可运行共用配置测试。

浏览器测试的开发依赖已固定在 `package-lock.json`。首次运行时安装：

```sh
npm ci
npx playwright install chromium
npm run test:e2e
```

`npm run test:browser` 是兼容别名。测试默认自行启动随机本机端口并在结束后关闭，覆盖真实剪贴板、导入、配置复制、刷新恢复、存储失败和手机布局；无需手动先启动服务。

可设置 `PALBOX_BASE_URL` 测试已有服务，`PALBOX_QA_OUTPUT` 指定截图与导入样例的输出目录（默认 `test-results/e2e`，已加入 Git 忽略）。Playwright 仅用于开发验收，生产运行不依赖它。
